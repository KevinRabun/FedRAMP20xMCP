# Migration Guide: FedRAMP Rev5 and FedRAMP 20x under CR26

## How CR26 treats Rev5

CR26 is one rule set with two Certification Types. A provider picks ONE type for a cloud service offering (FRC-CSO-POP): FedRAMP Rev5 Program Certification or FedRAMP 20x Program Certification. Rules are tagged by scope in the rules data: many apply to both types, some only to 20x (for example the KSI-oriented rules with the CSX group id, such as SDR-CSX-KSI, IVV-CSX-AIA, CPO-CSX-CPM, FRC-CSX-VVK, VDR-TFR-MVX) and some only to Rev5 (the CSF group id, such as SDR-CSF-CTF, IVV-CSF-AIA, CPO-CSF-CPM, VDR-TFR-MVF, FRC-CSF-*).

**Important Notes:**
- Rev5 Certification keeps NIST SP 800-53 Rev. 5 controls as the unit of assessment; 20x Certification uses the 46 Key Security Indicators (KSIs).
- The Certification Package Overview replaces the historically required System Security Plan for Rev5 (CPO-CSO-OVR notes). CR26 has no POA&M, SAR or OSCAL SSP requirement.
- Certification Data goes in a trust center in human-readable and JSON formats (CDS-CSO-UTC, CDS-CSO-PUB); OSCAL is not required.
- FedRAMP Ready status must be converted to a FedRAMP Certification by the later of the expiration of the annual assessment or November 17, 2026; legacy Ready status is removed on December 31, 2027 (FRC-CSF-RDY).

## Rev5-specific rules in CR26 (read each with get_frr_metadata)

- **FRC-CSF-BSL** FedRAMP Rev5 Baselines: Class B, C and D providers include the listed NIST SP 800-53 Rev. 5 controls in their Security Decision Record
- **FRC-CSF-ACP** Assign Control Parameters: assign all organization-defined parameters per FedRAMP Rev5 Controls Guidance and document them in the SDR (the CTL section of the rules data holds FedRAMP parameter values by control family: AC, AU, CA, CM, CP, IA, IR, MA, PS, RA, SA, SC, SI, SR)
- **FRC-CSF-FFG** Follow FedRAMP Rev5 Controls Guidance for implementation and documentation of applicable controls
- **FRC-CSF-RDY** FedRAMP Ready conversion (dates above)
- **FRC-APS-ATO** Agency Authorization to Operate: Rev5 Agency Certification requires a completed agency ATO with a signed ATO letter sent to FedRAMP
- **SDR-CSF-CTF** Rev5 Controls in the SDR: organization-defined parameter values, implementation status (Implemented, Partially Implemented, Planned, Alternative Implementation, Not Applicable), mechanisms, verification, validation, independent verification and validation, artifacts
- **IVV-CSF-AIA** Annual independent assessment of the listed Rev5 controls (once per year)
- **IVV-CSF-MCA** all applicable Rev5 controls assessed at least once every 3 years (a ceiling, not a floor); **IVV-CSF-PCA** SHOULD include all applicable controls in each assessment; **IVV-CSF-ACF** controls with negative findings go into the next assessment
- **CPO-CSF-CPM** Certification Package maintenance for Rev5 (by Class: at least yearly for B and C, at least every six months for D)
- **VDR-TFR-MVF** machine verification and validation for Rev5 (monthly)
- **CDS-CSF-TCM** Trust Center Migration: notify all necessary parties and leave instructions in existing USDA Connect Community Portal secure folders

## Executive Summary

**Key Changes (what CR26 emphasizes):**
- Document-based sharing becomes Certification Data in a trust center with programmatic access
- Annual cycle becomes persistent verification, validation and Ongoing Certification Reports every 3 months (CCM-OCR-AVL)
- Manual evidence becomes automated collection (see FRC-CSX-VVK for 20x)
- Severity-based remediation becomes VDR-TFR-PVR timeframes by Class, N-rating and reachability
- Rev5 controls (Rev5 type) or 46 KSIs (20x type)

Timeline and effort depend on your Class, Type and current maturity; plan your own schedule.

## Phase 1: Assessment and Planning

### Gap Analysis

**What you have (legacy Rev5):**
- System Security Plan (Word/PDF)
- Annual independent assessment
- Monthly ConMon scans and POA&M updates
- Manual evidence packages

**What CR26 expects (both types):**
- Certification Package with Overview and Security Decision Record, in human-readable and JSON (CPO-CSO-OVR, SDR-CSO-FRR)
- Trust center sharing (CDS-CSO-UTC)
- Ongoing Certification Report every 3 months (CCM-OCR-AVL) and Quarterly Review where your Class requires it (CCM-QTR-MTG)
- Vulnerability detection, evaluation and reporting (VDR, VER)
- Significant Change Notifications (SCN), incident reporting (IEC), FedRAMP Security Inbox (AFC)

### Current State Inventory

- [ ] Document the current ConMon process
- [ ] List evidence collection methods
- [ ] Review previous independent assessment findings (IVV-CSF-ACF)

### Map Rev5 control families to KSI families

The KSI definitions list the NIST controls they relate to. Based on those mappings in the rules data, the primary relationships are:
```
Rev5 family -> primary KSI families
AC  Access Control            -> IAM (also SVC, CNA, MLA)
AT  Awareness and Training    -> CED
AU  Audit and Accountability  -> MLA (also IAM)
CA  Assessment/Authorization  -> CNA, SCR, PIY
CM  Configuration Management  -> CMT, IAM, SVC, PIY
CP  Contingency Planning      -> RPL
IA  Identification/Auth.      -> IAM
IR  Incident Response         -> INR
PS  Personnel Security        -> IAM
RA  Risk Assessment           -> SCR, IAM, MLA, PIY
SA  System/Services Acq.      -> SCR
SC  System/Comms Protection   -> CNA, SVC, IAM
SI  System/Info Integrity     -> CNA, MLA, SVC, IAM
SR  Supply Chain Risk Mgmt    -> SCR, SVC
```
Rule-level equivalents: assessment and scope (MAS, IVV), vulnerabilities (VDR, VER), incidents (IEC), change (SCN), monitoring (CCM).

**Use compare_with_rev4 tool for legacy comparisons.** Always check the controls field of a KSI or rule (get_ksi, get_frr_metadata) for the authoritative mapping.

Likely already covered from Rev5 practice, needs documentation: authentication (KSI-IAM-APM), log review (KSI-MLA-RVL), incident procedures (KSI-INR-RIR), backups (KSI-RPL-ABO).

## Phase 3: Documentation Conversion

### From the SSP to the Certification Package
- Certification Package Overview (CPO-CSO-OVR) replaces the SSP front matter for Rev5
- Security Decision Record carries per-rule and per-control explanations, verification and validation (SDR-CSO-FRR, SDR-CSF-CTF or SDR-CSX-KSI)
- Control narratives map to SDR-CSF-CTF entries (Rev5) or KSI summaries (20x)
- Use `documentation_generator` for templates

### New documentation compared with legacy Rev5
1. Public information and service list (CDS-CSO-PUB, CDS-CSO-SVC)
2. Security Decision Record (SDR)
3. Secure Configuration Guide (SCG-CSO-RSC, SCG-CSO-AUP)
4. Cryptographic module documentation (CMU-CSO-CMD)
5. Ongoing Certification Report and Quarterly Review procedures (CCM-OCR-*, CCM-QTR-*)
6. For 20x: KSI implementation summaries (SDR-CSX-KSI)

## Phase 4: Process Changes

### Continuous monitoring (CCM)

**Legacy Rev5 process:**
- Monthly scans and ConMon deliverable
- Quarterly POA&M update
- Annual assessment

**CR26 process:**
- Persistent verification and validation (VDR-TFR-MVX for 20x, VDR-TFR-MVF for Rev5, by Class)
- Ongoing Certification Report every 3 months (CCM-OCR-AVL)
- Quarterly Review (CCM-QTR-MTG, by Class)
- Annual independent assessment (IVV-CSO-FIA; Rev5 controls per IVV-CSF-AIA)

### Vulnerability management (VDR, VER)

- Timeframes are not 30-day or severity based. VDR-TFR-PVR gives days from evaluation by Class, N-rating (Potential Agency Impact) and internet-reachability / exploitability
- Known Exploited Vulnerabilities follow CISA KEV due dates (VDR-TFR-KEV)
- Vulnerabilities not mitigated or remediated within 192 days of evaluation become accepted vulnerabilities (VER-TFR-MAV, VER-RPT-AVI); there is no POA&M
- Report at least monthly (VER-TFR-MHR)

**Action Items:**
- [ ] Review current remediation practices against VDR-TFR-PVR for your Class
- [ ] Automate detection (VDR-CSO-ADT) and evaluation (VER-EVA-*)
- [ ] Update procedures and reporting workflow

### Significant Change Notifications (SCN)
- Types: routine recurring (no formal notification), adaptive, transformative (SCN-CSO-EVA)
- Timing: SCN-ADP-NTF, SCN-TRF-NIP, SCN-TRF-NFP, SCN-TRF-NAF, SCN-TRF-NAV, SCN-TRF-UPD
- Maintain records and 12 months of notifications (SCN-CSO-MAR, SCN-CSO-HIS)

### Incidents (IEC) and FedRAMP communication (AFC)
- Evaluate reportability (IEC-CSO-EFR), default N5 (IEC-CSO-DPR), report on the Class and N-rating timeframes (IEC-CSO-IIR, IEC-CSO-OIR, IEC-CSO-FIR)
- Maintain the FedRAMP Security Inbox (AFC-CSO-INB)

## Common Migration Challenges

**Legacy tools lack APIs:** build middleware, replace tools, or use manual export with automation as a short-term workaround.

**Manual evidence collection:** automate with scripts and tools that track KSIs; see FRC-CSX-VVK for expected automation by Class.

**Machine-readable conversion:** convert Word/PDF content to the FedRAMP JSON schemas referenced in the rules (schema.url fields), not to OSCAL.

**Team knowledge gap:** train on CR26 (use this MCP server), phase the transition.

## Success Criteria

**Technical:**
- Trust center with programmatic access operating
- KSIs (20x) or controls (Rev5) tracked automatically
- JSON validates against FedRAMP schemas
- Continuous monitoring operational

**Process:**
- Ongoing Certification Reports and Quarterly Reviews on schedule
- Vulnerabilities handled within VDR-TFR-PVR timeframes
- Changes classified and notified per SCN
- Incidents handled per IEC

**Compliance:**
- Certification Package accepted by FedRAMP
- Agencies can access Certification Data
- Independent assessment results included (IVV-CSO-ICP)
