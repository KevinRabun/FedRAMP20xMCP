I'll help you prepare for your FedRAMP independent assessment and ongoing certification review under the FedRAMP Consolidated Rules for 2026 (CR26, version 2026.10.13.01).

# FedRAMP Independent Assessment Preparation Guide

**Scope note**: The week-by-week timeline below is an illustrative planning aid, not a CR26 requirement. Every concrete requirement quoted here cites a CR26 rule ID. CR26 has no requirement for a Plan of Action and Milestones (POA&M), a Security Assessment Report (SAR), or an OSCAL System Security Plan. Assessments are FedRAMP independent assessments (IVV family) performed by FedRAMP Recognized assessors (REC family).

### Evidence Gathering

**Organize evidence by KSI family:**

**KSI-IAM (Identity and Access Management):**
- [ ] Passwordless and phishing-resistant MFA coverage (KSI-IAM-APM)
- [ ] Automated account lifecycle management (KSI-IAM-AAM)
- [ ] Least privilege and just-in-time authorization (KSI-IAM-ELP, KSI-IAM-JIT)
- [ ] Non-user authentication (KSI-IAM-SNU)
- [ ] Response to suspicious activity (KSI-IAM-SUS)

**KSI-MLA (Monitoring, Logging, and Auditing):**
- [ ] SIEM configuration (KSI-MLA-OSM)
- [ ] Log review and audit evidence (KSI-MLA-RVL)
- [ ] Infrastructure as code configuration evaluation (KSI-MLA-EVC)
- [ ] List of logged event types and resources (KSI-MLA-LET)
- [ ] Log access authorization (KSI-MLA-ALA)

**VDR and VER (Vulnerability Detection, Response, Evaluation and Reporting):**
- [ ] Detection and response evidence (VDR-CSO-DET, VDR-CSO-RES)
- [ ] Reports matching VER-RPT-VDT fields and accepted vulnerabilities per VER-RPT-AVI
- [ ] Evidence of automated detection (VDR-CSO-ADT) and detection after changes (VDR-CSO-DAC)

**KSI-CMT (Change Management):**
- [ ] Change logging and monitoring (KSI-CMT-LMC)
- [ ] Redeployment of version-controlled resources (KSI-CMT-RMV)
- [ ] Automated testing and validation throughout deployment (KSI-CMT-VTD)
- [ ] Review of change procedures (KSI-CMT-RVP)

**KSI-INR (Incident Response):**
- [ ] Incident procedure reviews (KSI-INR-RIR)
- [ ] Review of past incidents (KSI-INR-RPI)
- [ ] After action reports (KSI-INR-AAR)
- [ ] Reportability evaluation log (IEC-CSO-EFR)

**KSI-RPL (Recovery Planning):**
- [ ] Recovery objectives (KSI-RPL-RRO)

- [ ] Recovery plan alignment (KSI-RPL-ARP)
- [ ] Recovery capability testing (KSI-RPL-TRC)

**KSI-CNA (Cloud Native Architecture):**
- [ ] Infrastructure as code templates and enforced intended state (KSI-CNA-EIS)
- [ ] Network restrictions and logical networking (KSI-CNA-RNT, KSI-CNA-ULN)
- [ ] Defined functionality and privileges (KSI-CNA-DFP)
- [ ] Minimized attack surface and availability optimization (KSI-CNA-MAT, KSI-CNA-OFA)

**KSI-SVC (Service Configuration):**
- [ ] Automated configuration management (KSI-SVC-ACM)
- [ ] Automated secret management (KSI-SVC-ASM)
- [ ] Encryption of information (KSI-SVC-SIN)
- [ ] Resource integrity validation (KSI-SVC-VRI)

**KSI-SCR (Supply Chain Risk):**
- [ ] Supply chain risk mitigation and monitoring (KSI-SCR-MIT, KSI-SCR-MON)

**KSI-PIY, KSI-CED (Policy, Inventory and Education):**
- [ ] Automatically generated inventories (KSI-PIY-GIV)
- [ ] Training effectiveness review (KSI-CED-RAT)

### Technical Testing

**Certification Data Sharing and Trust Center Testing:**

**Functionality Tests:**
- [ ] Public information available in human-readable and JSON formats (CDS-CSO-PUB)
- [ ] Programmatic access documented and working (CDS-TRC-PAC)
- [ ] Machine-readable data validates against FedRAMP JSON schemas where defined (FRC-CSO-JSN)
- [ ] Human-readable and machine-readable data stay consistent via automation (CDS-CSO-CBF)
- [ ] Access without interruption (CDS-TRC-USH)

**Security Tests:**
- [ ] Authentication required for non-public data
- [ ] No sensitive data leakage (CDS-CSO-RIS)
- [ ] Access logging with summaries retained for at least six months (CDS-TRC-ACL)
- [ ] Agency access inventory available (CDS-TRC-AAI)

**Data Accuracy Tests:**
- [ ] Service list matches the Minimum Assessment Scope (CDS-CSO-SVC)
- [ ] Vulnerability reports current per your reporting cycle (VER-RPT-PER, VER-TFR-MHR at least monthly)
- [ ] KSI metrics accurate
- [ ] Incident and significant change data complete

**Use validate_architecture tool to check your implementation.**

**KSI Validation Testing (all 46 KSIs):**
- [ ] Evidence collection automated where applicable
- [ ] Metrics accurate and current
- [ ] Target values being met
- [ ] Alerting working for out-of-compliance conditions

**Priority KSIs to test thoroughly:**
- KSI-IAM-APM: passwordless / phishing-resistant authentication
- KSI-MLA-OSM: SIEM
- KSI-MLA-EVC: infrastructure as code evaluation
- VDR-CSO-DET: vulnerability detection
- KSI-CMT-VTD: automated testing
- KSI-CNA-DFP: defined functionality and privileges

### Process Validation

**Ongoing Certification procedures:**
- [ ] Produce an Ongoing Certification Report covering the full period since the previous one (CCM-OCR-AVL, every 3 months)
- [ ] Verify all data collected automatically
- [ ] Test the Quarterly Review process (CCM-QTR-MTG, strength varies by class)

**Vulnerability management:**
- [ ] Test vulnerability discovery process (VDR-CSO-DET)
- [ ] Verify tracking against VDR-TFR-PVR timeframes (by Certification Class, N-rating and reachability)
- [ ] Verify accepted vulnerability handling (VER-TFR-MAV, VER-RPT-AVI)

**Incident response:**
- [ ] Conduct tabletop exercise
- [ ] Test reporting procedures (IEC-CSO-IIR, IEC-CSO-OIR, IEC-CSO-FIR)
- [ ] Validate logging and documentation (IEC-CSO-EFR)

**Change management:**
- [ ] Review recent changes
- [ ] Validate categorization (SCN-CSO-EVA)
- [ ] Verify approval process and notification content (SCN-CSO-INF)

### Final Preparation

**Team readiness:**
- [ ] Identify key personnel for interviews
- [ ] Prepare staff for questions
- [ ] Schedule availability for assessment period
- [ ] Create contact list for the assessor

**Technical access:**
- [ ] Provide the assessor read-only access to evidence and systems
- [ ] Supply evidence of implementation and effectiveness (IVV-CSO-SEI, IVV-CSO-SEE)
- [ ] Prepare technical explanations and demonstrations (IVV-CSO-STE)
- [ ] Document any use of representative samples (IVV-CSO-DUS)

**Documentation finalization:**
- [ ] All documents version-controlled and dated
- [ ] All references consistent
- [ ] All diagrams current

## During Assessment

Assessors verify implementation (IVV-IAS-VIM) and validate effectiveness (IVV-IAS-VEF), then supply the provider with a summary of the assessment and an overall summary (IVV-IAS-SUM, IVV-IAS-OSA).

### Kickoff and Documentation Review
- System overview and trust center walkthrough
- Review assessment schedule
- Answer clarifying questions promptly and track all requests
- Assign one person as the assessor liaison

### Technical Testing
- Trust center and JSON schema validation
- Infrastructure and configuration reviews
- Access control testing
- Log analysis

### Interviews and Validation

**Common interview topics:**
- System owner/ISSO: architecture, KSI implementation, Ongoing Certification approach, incident procedures
- Development team: secure development, CI/CD, code review, testing
- Operations team: configuration management, patching, backup and recovery, monitoring
- Security team: vulnerability management, log analysis, incident response

**Tips:**
- Answer honestly; say "I don't know" if unsure
- Provide evidence when possible
- Keep answers concise

### Handling Findings

CR26 does not define critical/high/moderate/low finding buckets or a POA&M process. Provider obligations come from the rules:
- Vulnerabilities found are handled under VDR-CSO-RES, evaluated under VER-EVA-*, and mitigated or remediated on the VDR-TFR-PVR timeframes; anything not fully mitigated or remediated within 192 days of evaluation is an accepted vulnerability (VER-TFR-MAV)
- Problems or failures in your detection and response processes are themselves vulnerabilities (VDR-CSO-FAV)
- Rev5 controls with negative findings from the previous assessment must be included in the next assessment (IVV-CSF-ACF)

**Response strategy:**
- Quick fixes: remediate immediately and record the evidence
- Longer fixes: track through your vulnerability response process and report per VER-RPT-PER
- Process issues: update procedures, retrain staff, and update the Security Decision Record

## Post-Assessment Activities

### Immediate actions
- Debrief and review all assessor findings
- Prioritize remediation and assign owners

### Assessment results
- [ ] Review the assessor's summaries for accuracy
- [ ] Include the independent assessment results in the Certification Package (IVV-CSO-ICP)
- [ ] Keep Certification Data current (CPO-CSX-CPM for 20x, CPO-CSF-CPM for Rev5; frequency varies by class)
- [ ] Plan the next annual independent assessment (IVV-CSO-FIA; KSIs for 20x per IVV-CSX-AIA, Rev5 controls per IVV-CSF-AIA)

### Certification Package submission
- [ ] Certification Package per FRC-CSO-PKG
- [ ] FedRAMP JSON schema validation (FRC-CSO-JSN)
- [ ] Certification Data published through your trust center (CDS-CSO-UTC)
- [ ] Responsibility for accuracy retained, even when third parties supply data (FRC-CSO-MRA)

## Common Findings

### Frequent gaps

**1. Certification Data Sharing issues**
- Trust center programmatic access missing or undocumented (CDS-TRC-PAC)
- JSON fails schema validation (FRC-CSO-JSN)
- Human and machine-readable data inconsistent (CDS-CSO-CBF)
- Prevention: test thoroughly, validate against schemas, automate data refresh

**2. KSI evidence not automated**
- Manual evidence collection, evidence not current, no automated metrics
- Prevention: see FRC-CSX-VVK for the automated method expectations by class; build dashboards for all KSIs

**3. Authentication not phishing-resistant (KSI-IAM-APM)**
- SMS or TOTP only, incomplete coverage
- Prevention: passwordless or phishing-resistant MFA (for example FIDO2/WebAuthn or PIV/CAC) for all users

**4. Incomplete logging (KSI-MLA-OSM, KSI-MLA-LET)**
- Not all log sources captured, logs not centralized
- Prevention: inventory all log sources and maintain the list of logged event types (KSI-MLA-LET). CR26 does not set a numeric log retention period; set retention from your own risk analysis and any applicable control parameters (CTL data in the rules JSON)

**5. Vulnerability response gaps (VDR, VER)**
- Vulnerabilities not evaluated or not mitigated within VDR-TFR-PVR timeframes; no tracking process; missing evidence
- Prevention: automated detection and tracking (VDR-CSO-ADT), alerts for overdue vulnerabilities, report monthly or more often (VER-TFR-MHR)

**6. Infrastructure not managed as code (KSI-MLA-EVC, KSI-CNA-EIS)**
- Manual provisioning, configuration drift
- Prevention: Bicep/Terraform/ARM in version control

**7. Inadequate validation in deployment (KSI-CMT-VTD)**
- No automated testing in CI/CD; security tests not automated

**8. Incomplete Minimum Assessment Scope (MAS)**
- Missing information resources or third-party resources (MAS-CSO-IIR, MAS-CSO-TPR)
- Inaccurate information flows (MAS-CSO-FLO)

**9. Inadequate Ongoing Certification (CCM)**
- Reports late or incomplete (CCM-OCR-AVL), no feedback mechanism (CCM-OCR-FBM), next report date not published (CCM-OCR-NRD)

**10. Incomplete documentation**
- Procedures not documented, documentation out of date
- Prevention: use the documentation_generator prompt, keep docs in version control

### KSI-specific common findings

- KSI-IAM: privileged access not monitored; non-user accounts not inventoried
- KSI-MLA: alert rules not tuned; SIEM not configured properly
- KSI-CMT: changes not logged; no redeployment practice
- KSI-INR: no incident response review; after action reports not produced
- KSI-RPL: backups not aligned with recovery objectives; recovery not tested
- KSI-CNA: no network restriction review; privileges not strictly defined
- KSI-SVC: secrets not rotated automatically; configuration not automated
- KSI-SCR: third-party software not monitored for upstream vulnerabilities

- [ ] Complete all KSI implementations

## Success Factors

**What makes a successful assessment:**
- Complete, accurate documentation
- Working trust center and programmatic access
- Automated evidence collection for KSIs
- Well-prepared, knowledgeable team
- Responsive to assessor requests
- Honest communication about any gaps
- Quick remediation of identified issues

**Red flags to avoid:**
- Incomplete documentation
- Trust center or data feeds not working during assessment
- Team unfamiliar with procedures
- Evidence not available
- Defensive attitude toward findings
- Lack of preparation

Remember: the assessor is not your adversary. Be honest, prepared, and responsive, and you'll have a successful assessment.
