I'll provide a roadmap for starting your FedRAMP 20x certification from scratch under the FedRAMP Consolidated Rules for 2026 (CR26, version 2026.10.13.01).

# FedRAMP 20x Initial Assessment Roadmap

**Important Notes:**
- CR26 uses FedRAMP Certification (Classes A, B, C, D; types 20x and Rev5), not Authorization to Operate by impact level. Many rules vary by Class (see FRD-CCL).
- Certification Data is shared through a trust center in human-readable and JSON formats (CDS-CSO-UTC, CDS-CSO-PUB). OSCAL is not required.
- CR26 has no POA&M, SAR, or OSCAL SSP requirement. Documentation is the Certification Package (FRC-CSO-PKG) with its Certification Package Overview (CPO-CSO-OVR) and Security Decision Record (SDR-CSO-FRR).
- Providers must be listed in the FedRAMP Marketplace before applying (FRC-APP-MLF).

## Phase 1: Foundation

**Understanding and Planning**
- [ ] Review the CR26 rules (use list_frrs_by_family for each family; 17 families, 245 rules)
- [ ] Choose a Certification Class and Type (FRC-CSO-FCP, FRC-CSO-POP: pick 20x or Rev5, not both)
- [ ] Determine service model (SaaS, PaaS, IaaS)
- [ ] Assemble core team (CISO, compliance PM, engineering lead)
- [ ] Budget for a FedRAMP Recognized assessor, tools, and staff time (REC family)

**Initial Scoping (MAS)**
- [ ] Identify information resources in the cloud service offering (MAS-CSO-IIR)
- [ ] Document federal customer data flows and security categories (MAS-CSO-FLO)
- [ ] Identify third-party dependencies (MAS-CSO-TPR)
- [ ] Review FRD definitions for terminology

**Deliverables**: Scope diagram, resource inventory, project charter

## Phase 2: Infrastructure and Tools

**Security Monitoring**
- [ ] Select and deploy SIEM (KSI-MLA-OSM)
- [ ] Configure log forwarding from all systems and maintain the list of logged event types (KSI-MLA-LET)
- [ ] Set up vulnerability detection (VDR-CSO-DET)
- [ ] Implement container/code scanning
- [ ] Configure alerting and dashboards

**Identity and Access**
- [ ] Adopt passwordless / phishing-resistant authentication (KSI-IAM-APM)
- [ ] Ensure least privilege (KSI-IAM-ELP)
- [ ] Automate account management (KSI-IAM-AAM)
- [ ] Document access procedures

**Automation Foundation**
- [ ] Evaluate configuration, especially infrastructure as code (KSI-MLA-EVC)
- [ ] Set up CI/CD with automated testing and validation (KSI-CMT-VTD)
- [ ] Implement secret management (KSI-SVC-ASM)

**Deliverables**: Operational SIEM, vulnerability detection, strong authentication, IaC

## Phase 3: Compliance Infrastructure

**KSI Tracking**
- [ ] Review all 46 KSIs (use list_ksi)
- [ ] Map KSIs to your monitoring systems
- [ ] Implement automated KSI verification (see FRC-CSX-VVK for expected automated methods by Class)
- [ ] Create KSI dashboards
- [ ] Document collection procedures

**Certification Data Sharing**
- [ ] Choose a FedRAMP-compatible trust center (CDS-CSO-UTC)
- [ ] Publish public information in human-readable and JSON (CDS-CSO-PUB, CDS-CSO-SVC)
- [ ] Provide documented programmatic access (CDS-TRC-PAC)
- [ ] Validate JSON against FedRAMP schemas (FRC-CSO-JSN)
- [ ] Automate consistency between formats (CDS-CSO-CBF)

**Ongoing Certification Setup (CCM)**
- [ ] Plan the Ongoing Certification Report every 3 months (CCM-OCR-AVL)
- [ ] Plan Quarterly Reviews (CCM-QTR-MTG; strength varies by Class)
- [ ] Set up persistent verification and validation (VDR-TFR-MVX for 20x)
- [ ] Set up a feedback mechanism (CCM-OCR-FBM)

**Deliverables**: KSI collection system, trust center, Ongoing Certification procedures

## Phase 4: Documentation

**Core Documentation**
- [ ] Certification Package Overview (CPO-CSO-OVR)
- [ ] Security Decision Record (SDR-CSO-FRR, SDR-CSX-KSI)
- [ ] Vulnerability Detection, Response, Evaluation and Reporting procedures (VDR, VER)
- [ ] Incident Evaluation and Communication procedures (IEC)
- [ ] Significant Change Notification procedures (SCN)
- [ ] Secure Configuration Guide (SCG-CSO-RSC)

**Policies and Procedures**
- [ ] Security policies, listed per CDS-CSO-IRP
- [ ] Change management procedures (KSI-CMT-RVP)
- [ ] Incident response procedures (KSI-INR-RIR)
- [ ] Recovery plan (KSI-RPL-ARP)
- [ ] Training reviews (KSI-CED-RAT)

**Evidence Collection**
- [ ] Configure automated evidence collection
- [ ] Validate all KSI measures are tracked
- [ ] Generate a sample Ongoing Certification Report
- [ ] Document evidence collection procedures

**Deliverables**: Certification Package, policies and procedures, evidence collection system

## Phase 5: Assessment Preparation

**Internal Readiness**
- [ ] Internal assessment
- [ ] Gap remediation
- [ ] Evidence validation
- [ ] Practice runs with team

**Independent Assessor Engagement (IVV, REC)**
- [ ] Select a FedRAMP Recognized assessor (only recognized assessors count: REC-FRP-RAO)
- [ ] Provide evidence of implementation and effectiveness (IVV-CSO-SEI, IVV-CSO-SEE)
- [ ] Complete the independent assessment (a fresh initial assessment is expected, FRC-APP-FIA)

**Deliverables**: Assessor results for the Certification Package (IVV-CSO-ICP)

## Phase 6: Certification

**Application**
- [ ] Be listed in the FedRAMP Marketplace (FRC-APP-MLF)
- [ ] Complete the Certification Application Form yourself, not via a third party (FRC-APP-AFC, FRC-APP-NTP)
- [ ] Supply a fresh Certification Package (FRC-APP-FCP)

**Review**
- [ ] FedRAMP reviews the package
- [ ] Respond to questions and provide additional evidence

**Deliverables**: FedRAMP Certification

## Ongoing: Ongoing Certification

Cadences below come from the rules; take Class-specific values from the rules data.
- Ongoing Certification Report every 3 months (CCM-OCR-AVL)
- Quarterly Review (CCM-QTR-MTG)
- Vulnerability reporting at least monthly (VER-TFR-MHR)
- Non-machine resource verification at least every 3 months (VDR-TFR-NMV)
- Certification Package maintenance (CPO-CSX-CPM for 20x, by Class)
- Annual independent assessment (IVV-CSO-FIA)
- Significant Change Notifications as changes occur (SCN)

## Critical Success Factors

**1. Executive Support** (KSI-PIY-RES)
- Secure budget and resources
- Ensure priority status

**2. Automation First** (see the FRD definition of "Persistently" and FRC-CSX-VVK)
- Automate evidence collection
- Use IaC for infrastructure
- Implement CI/CD pipelines

**3. Team Skills**
- CR26 knowledge
- Cloud-native expertise
- Security automation skills

**4. Vendor Selection**
- Choose tools with APIs for automation
- Check KSI alignment
- Confirm trust center compatibility

## Timeline and Resource Planning

Engineering teams should determine their own timelines based on available resources, organizational requirements, infrastructure maturity, and compliance readiness. Effective dates differ by family (see each family's effective block in the rules data).
