## Bicep Template for VDR and VER (Vulnerability Detection, Response, Evaluation and Reporting)

```bicep
// frr_vdr.bicep - Vulnerability Management Infrastructure
// Infrastructure sketch for vulnerability detection, response, evaluation and reporting
// under the FedRAMP Consolidated Rules for 2026 (CR26). VDR and VER are required from 2026-12-07
// (mandated by CISA BOD 26-04).
//
// Rules supported:
// - VDR-CSO-DET, VDR-CSO-RES: Vulnerability detection and response
// - VDR-CSO-ADT, VDR-CSO-DAC: Automated detection, detection after changes
// - VDR-TFR-PVR: Mitigation and remediation timeframes (by Class, N-rating, reachability)
// - VDR-TFR-KEV: Known Exploited Vulnerabilities per CISA due dates
// - VER-EVA-ELX, VER-EVA-EIR, VER-EVA-EPA: Exploitability, reachability, potential agency impact
// - VER-RPT-PER, VER-RPT-VDT, VER-RPT-AVI: Reporting and accepted vulnerabilities
// - VER-TFR-MHR: Report at least monthly
// - VER-TFR-MAV: Accepted vulnerability after 192 days from evaluation
//
// Related rules and KSIs:
// - MAS-CSO-IIR: Scope of information resources
// - KSI-SCR-MON: Supply chain risk monitoring
// - KSI-PIY-GIV: Generating inventories

targetScope = 'resourceGroup'

param location string = resourceGroup().location
param workspaceName string = 'vdr-compliance-${uniqueString(resourceGroup().id)}'
param storageAccountName string = 'vdrevidence${uniqueString(resourceGroup().id)}'
param defenderEnabled bool = true
@description('Log retention in days. Organization-defined: CR26 sets no numeric log retention period.')
param logRetentionDays int

// Log Analytics Workspace for vulnerability scan logs
// Retention is organization-defined (CR26 sets no numeric log retention period)
resource logAnalytics 'Microsoft.OperationalInsights/workspaces@2023-09-01' = {
  name: workspaceName
  location: location
  properties: {
    sku: {
      name: 'PerGB2018'
    }
    retentionInDays: logRetentionDays  // organization-defined
    features: {
      enableLogAccessUsingOnlyResourcePermissions: true
    }
    publicNetworkAccessForIngestion: 'Enabled'
    publicNetworkAccessForQuery: 'Enabled'
  }
}

// Storage Account for vulnerability reports and evidence
// Supports: VER-RPT-PER (reports are Certification Data), CDS-CSO-CBF (consistent human and machine-readable formats)
resource storageAccount 'Microsoft.Storage/storageAccounts@2023-01-01' = {
  name: storageAccountName
  location: location
  sku: {
    name: 'Standard_GRS'  // Geo-redundant for compliance evidence
  }
  kind: 'StorageV2'
  properties: {
    minimumTlsVersion: 'TLS1_2'
    supportsHttpsTrafficOnly: true
    allowBlobPublicAccess: false
    networkAcls: {
      defaultAction: 'Deny'
      bypass: 'AzureServices'
    }
    encryption: {
      requireInfrastructureEncryption: true
      services: {
        blob: {
          enabled: true
          keyType: 'Account'
        }
      }
      keySource: 'Microsoft.Storage'  // design default for production: customer-managed keys (KSI-SVC-ASM)
    }
  }
}

// Blob Container for vulnerability scan results
// Supports: VDR-CSO-DET (detection results), VER-RPT-VDT (report inputs)
resource scanResultsContainer 'Microsoft.Storage/storageAccounts/blobServices/containers@2023-01-01' = {
  name: '${storageAccount.name}/default/vulnerability-scans'
  properties: {
    publicAccess: 'None'
    metadata: {
      purpose: 'Vulnerability detection results (VDR-CSO-DET)'
    }
  }
}

// Blob Container for remediation tracking
// Supports: VDR-TFR-PVR (mitigation and remediation timeframes)
resource remediationContainer 'Microsoft.Storage/storageAccounts/blobServices/containers@2023-01-01' = {
  name: '${storageAccount.name}/default/remediation-tracking'
  properties: {
    publicAccess: 'None'
    metadata: {
      purpose: 'Mitigation and remediation tracking (VDR-TFR-PVR)'
    }
  }
}

// Blob Container for accepted vulnerabilities
// Supports: VER-TFR-MAV, VER-RPT-AVI
resource acceptedVulnerabilitiesContainer 'Microsoft.Storage/storageAccounts/blobServices/containers@2023-01-01' = {
  name: '${storageAccount.name}/default/accepted-vulnerabilities'
  properties: {
    publicAccess: 'None'
    metadata: {
      purpose: 'Accepted vulnerability information (VER-RPT-AVI)'
    }
  }
}

// Action Group for vulnerability alerts
// Supports: VDR-CSO-RES (response tracking), VDR-TFR-PVR (deadline alerts)
resource actionGroup 'Microsoft.Insights/actionGroups@2023-01-01' = {
  name: 'vdr-compliance-alerts'
  location: 'global'
  properties: {
    groupShortName: 'VDRAlerts'
    enabled: true
    emailReceivers: [
      {
        name: 'Security Team'
        emailAddress: 'security@contoso.com'
        useCommonAlertSchema: true
      }
      {
        name: 'Compliance Team'
        emailAddress: 'compliance@contoso.com'
        useCommonAlertSchema: true
      }
    ]
  }
}

// Alert Rule: Vulnerabilities past their VDR-TFR-PVR target
// The RemediationDeadline column is assumed to be computed upstream from the VDR-TFR-PVR table for your
// Certification Class using the vulnerability's N-rating, internet-reachability and likely exploitability.
// Supports: VDR-TFR-PVR, VDR-TFR-KEV
resource criticalVulnAlert 'Microsoft.Insights/scheduledQueryRules@2023-03-15-preview' = {
  name: 'vuln-past-pvr-target'
  location: location
  properties: {
    displayName: 'Vulnerabilities Past Mitigation or Remediation Target'
    description: 'Alerts when vulnerabilities pass the VDR-TFR-PVR target for their N-rating and reachability (VDR-TFR-PVR)'
    severity: 0  // Critical
    enabled: true
    evaluationFrequency: 'PT1H'
    scopes: [
      logAnalytics.id
    ]
    windowSize: 'P1D'
    criteria: {
      allOf: [
        {
          query: '''
            SecurityVulnerability
            | where NRating >= 3
            | where RemediationDeadline < now()
            | summarize Count = count() by VulnerabilityId, AffectedResource
          '''
          timeAggregation: 'Count'
          operator: 'GreaterThan'
          threshold: 0
          failingPeriods: {
            numberOfEvaluationPeriods: 1
            minFailingPeriodsToAlert: 1
          }
        }
      ]
    }
    actions: {
      actionGroups: [
        actionGroup.id
      ]
    }
  }
}

// Microsoft Defender for Cloud configuration (optional but recommended)
// Supports: VDR-CSO-DET, VDR-CSO-ADT (automated detection)
resource defenderForServers 'Microsoft.Security/pricings@2024-01-01' = if (defenderEnabled) {
  name: 'VirtualMachines'
  properties: {
    pricingTier: 'Standard'
    subPlan: 'P2'
  }
}

resource defenderForContainers 'Microsoft.Security/pricings@2024-01-01' = if (defenderEnabled) {
  name: 'Containers'
  properties: {
    pricingTier: 'Standard'
  }
}

// Automation Account for scheduled vulnerability reporting
// Supports: VER-RPT-PER (reporting), VER-TFR-MHR (at least monthly reports), VDR-TFR-KEV (KEV tracking)
resource automationAccount 'Microsoft.Automation/automationAccounts@2023-11-01' = {
  name: 'vdr-automation-${uniqueString(resourceGroup().id)}'
  location: location
  identity: {
    type: 'SystemAssigned'
  }
  properties: {
    sku: {
      name: 'Basic'
    }
    encryption: {
      keySource: 'Microsoft.Automation'
    }
  }
}

// Outputs for integration with CI/CD and evidence collection
output workspaceId string = logAnalytics.id
output workspaceCustomerId string = logAnalytics.properties.customerId
output storageAccountName string = storageAccount.name
output scanResultsContainerUrl string = '${storageAccount.properties.primaryEndpoints.blob}vulnerability-scans'
output remediationContainerUrl string = '${storageAccount.properties.primaryEndpoints.blob}remediation-tracking'
output automationAccountName string = automationAccount.name
```

## Deployment Instructions

1. **Create Resource Group:**
   ```bash
   az group create --name rg-vdr-compliance --location eastus
   ```

2. **Deploy Template:**
   ```bash
   az deployment group create \
     --resource-group rg-vdr-compliance \
     --template-file frr_vdr.bicep \
     --parameters defenderEnabled=true
   ```

3. **Configure Vulnerability Scanning:**
   - Enable Defender for Cloud vulnerability assessments
   - Integrate with Trivy, Qualys, or Tenable (authenticated scanning improves coverage of VDR-CSO-DET)
   - Configure CI/CD pipeline to upload scan results to blob storage

4. **Set Up Evidence Collection:**
   - Create Azure Function to collect detection results (cadence per VDR-TFR-PDD, VDR-TFR-PCD, VDR-TFR-PSD for your Class)
   - Store results in `vulnerability-scans` container
   - Generate reports at least monthly (VER-TFR-MHR) including the VER-RPT-VDT fields and KEV status

5. **Configure Remediation Tracking:**
   - Set up automated tracking for vulnerability remediation
   - Calculate target dates from the VDR-TFR-PVR table for your Class (N-rating x internet-reachability x exploitability); flag vulnerabilities not mitigated or remediated within 192 days of evaluation as accepted (VER-TFR-MAV)
   - Alert when deadlines are approaching or exceeded

## Evidence Artifacts (Certification Data, CDS-CSO-CBF)

**Machine-Readable Formats:**
- `vulnerability-scans/YYYY-MM-DD-scan-results.json` - Daily scan results
- `remediation-tracking/YYYY-MM-DD-remediation-status.json` - Remediation progress
- `accepted-vulnerabilities/YYYY-MM-DD-accepted.json` - Accepted vulnerabilities (VER-RPT-AVI)

**Collection Schedule:**
- Detection: per VDR-TFR-PDD, VDR-TFR-PCD, VDR-TFR-PSD for your Class (automated in CI/CD where possible)
- Remediation status: as often as your reporting needs
- Vulnerability report: at least monthly (VER-TFR-MHR)
- Ongoing Certification Report inputs: every 3 months (CCM-OCR-AVL)

## Related Rules

- **VDR-CSO-DET**: Vulnerability detection implementation (this template)
- **VDR-TFR-PVR**: Timeframes by Class, N-rating and reachability (alert rule; the deadline calculation is yours to implement)
- **VER-EVA-EIR**: Evaluate internet-reachability (requires process documentation)
- **VER-RPT-HLO**: High-level overviews of all detection and response activity (SHOULD)
- **VER-TFR-MHR**: Monthly report (this template provides storage and automation)
- **VER-TFR-MAV, VER-RPT-AVI**: Accepted vulnerabilities (container and reporting fields)
- **VDR-TFR-KEV**: KEV remediation by CISA due dates
- **VER-RPT-PER**: Persistent reporting as Certification Data
